### Задание 1.

Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования.

Необходимо описать, какие варианты резервного копирования подходят в случаях:

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

1.1 Для полного восстановления данных за предыдущий день подходит резервное копирование, выполняемое ежедневно. Оно захватывает всю базу в момент создания копии, что позволяет полностью восстановить состояние на конец предыдущего дня без потерь.

1.2 Для восстановления за час до поломки идеален инкрементный (incremental) или дифференциальный backup в комбинации с WAL-логами (Write-Ahead Logging) в PostgreSQL или binary logs в MySQL. Полный бэкап делается раз в сутки, а инкрементные — ежечасно; при восстановлении применяются логи изменений до нужного времени (point-in-time recovery).


1.3 Да, такой кейс возможен через репликацию (replication): настройте master-slave или кластер (например, PostgreSQL streaming replication или MySQL Group Replication). При поломке primary происходит автоматическое переключение (failover) на slave с минимальной задержкой (секунды), используя инструменты вроде Patroni или Orchestrator

### Задание 2.

2.1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (pgdump/pgrestore).

2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?


Пример команды резервного копирования из официальной документации:  pg_dump -h hostname -p 5432 -U username -Fc -b -v -f dumpfile.sql -d database_name . Это создаёт сжатый архив в custom-формате с данными и схемой.

Для восстановления нужно выполнить команду:  pg_restore -h hostname -p 5432 -U username -d dbname -v dumpfile.sql  (или с  -C  для создания БД,  -j 4  для параллельного восстановления).


Автоматизировать возможно через cron-скрипты: создайте bash-скрипт с pg_dump (например, ежедневно в 2:00:  0 2 * * * /path/to/backup.sh ), добавьте ротацию файлов и логирование ошибок. Для контейнеров — Kubernetes CronJob

### Задание 3.

Задание 3. MySQL

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?
 
Для инкрементного бэкапа нужно использовать binary logs: сначала включить их в my.cnf ( log-bin=mysql-bin server-id=1 ), затем полный бэкап mysqldump, flush logs ( mysqladmin -u root -p flush-logs ) и копировать новые bin-файлы. Восстановление: mysqldump + mysqlbinlog с –start-position.


Репликация даёт преимущества над обычным бэкапом в случаях высокой доступности (failover без downtime), распределения нагрузки (read-реплики для аналитики), гео-распределения данных и live-бэкапа без блокировки master
